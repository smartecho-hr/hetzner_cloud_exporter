# Contributing

Issues and pull requests are welcome. For larger changes (a new collector, metric renames),
please open an issue first.

## Checks

Run these before sending a pull request; CI runs the same:

```sh
go vet ./...
go test ./... -race -cover
go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.14.0 run ./...
docker run --rm -v "$PWD/prometheus:/rules:ro" -w /rules --entrypoint promtool \
  prom/prometheus:v3.15.0 test rules alerts_test.yml
docker run --rm -v "$PWD/grafana-dashboards/test:/rules:ro" -w /rules --entrypoint promtool \
  prom/prometheus:v3.15.0 test rules dashboards_test.yml
```

Tests use a fake Hetzner API (`internal/hcloudtest`), never the real one.

## Conventions

- **Scrapes never call the Hetzner API.** API calls belong in a source's `Fetch` (run by the
  background poller); `Collect` only reads stored data.
- **A new Hetzner resource** is a new package under `internal/sources/` implementing
  `poller.Source`, registered in `internal/sources/sources.go`, with a collector toggle.
- **Mind the rate limit** (3600 requests per hour per project): avoid per-item requests, or
  make them optional and interval-based.
- **Every option** is a command line flag, an environment variable and a `config.yaml` key, and
  is documented in `config.example.yaml`, `docker/.env.example` and `README.md`
  (`TestEveryOptionInEveryPlace` checks this).
- **Metric names:** `hetzner_cloud_<subsystem>_<name>_<unit>`, base units (bytes, seconds).
  Renaming a metric or label is a breaking change: update `prometheus/alerts.yml`, the
  dashboards and `CHANGELOG.md`.
- **Alerts and dashboard queries** aggregate by the metric's own labels and `job`
  (`max by (job, load_balancer) (...)`), never by `instance`.
- Every alert has a promtool test in `prometheus/alerts_test.yml`.
- Every dashboard query has a test: `grafana-dashboards/test/queries.yml` holds each panel query
  as a recording rule (generated, don't edit) and `dashboards_test.yml` checks its result on
  known data. After changing a dashboard, run `go test ./internal/dashboards -update` and add or
  adjust the expectations; `go test ./...` fails if a query has no test or isn't limited to
  `job="$job"`.
- The Grafana dashboards in `grafana-dashboards/` are generated by a maintainer tool; for
  dashboard changes, open an issue or a pull request with the changed JSON, and the change will
  be carried over into the generator.

Add a line to `CHANGELOG.md` (section *Unreleased*) for anything users notice.
